LANGKAH 4 — UPLOAD DAN DOWNLOAD DOKUMEN PDF

A. CIPTA BUCKET (SEKALI SAHAJA)
Buka Supabase project Jala-Mutu, bukan Sistem Monitoring.
Storage > New bucket.
Name: dokumen-persiapan
Public bucket: OFF (private).
Jika ada tetapan saiz: 10 MB / 10485760 bytes.
Allowed MIME types: application/pdf.
Cipta bucket. Jika had saiz/MIME tidak ada dalam dialog awal, buka bucket settings selepas dicipta dan tetapkan di situ.
Bucket BELUM dibuat oleh assistant; polisi akses dan fungsi database SUDAH dipasang. Jangan run SQL lagi.

B. PASANG UPDATE
1. Hentikan backend di terminal: Ctrl+C.
2. Backup folder backend.
3. Extract ZIP, copy kandungan folder backend ke backend asal; pilih Replace. Jangan buat backend/backend.
4. .env tidak perlu diubah. Tiada service_role/secret key diperlukan.
5. Dalam terminal folder backend:
   npm install
   npm run typecheck
   npm test
   npm run dev
Ada 49 ujian HTTP simulasi; semuanya sepatutnya lulus. Multer ditambah untuk menerima upload multipart/form-data.

C. UJI MELALUI POSTMAN SECARA MANUAL
Login Penyedia seperti dahulu untuk mendapatkan token baru.
POST http://localhost:5000/api/paket/3/dokumen
Authorization > Bearer Token: token Penyedia.
Body > form-data (BUKAN raw JSON):
Key                Type    Value
judul              Text    UJIAN - Laporan Pendahuluan
jenis_dokumen      Text    LAPORAN_PENDAHULUAN
file               File    Pilih satu PDF kecil dari laptop

Pada baris file, tukar Text menjadi File menggunakan dropdown, kemudian pilih fail.
Jangan tetapkan header Content-Type sendiri; Postman memasukkan boundary multipart secara automatik.
Klik Send sekali. Status sepatutnya 201. Simpan dokumen_id daripada data.dokumen.dokumen_id.
Jenis kedua yang dibenarkan: PROGRAM_MUTU.

D. BACA SENARAI
GET http://localhost:5000/api/paket/3/dokumen
Bearer Token Penyedia, Body none.
Status 200 dan dokumen yang baru diupload muncul.

E. DOWNLOAD
GET http://localhost:5000/api/paket/3/dokumen/ID_DOKUMEN/download
Ganti ID_DOKUMEN dengan ID sebenar respons upload. Body none.
Gunakan pilihan Save Response dalam Postman untuk menyimpan PDF.
Uji token PIC DKI-Jabar: boleh download. Uji token PIC Kalteng: 404. PIC tidak boleh upload (403).

F. KOLEKSI PILIHAN
Import backend/postman/Jala-Mutu-Langkah-4.postman_collection.json.
Isi Variables seperti dahulu dan paket_id=3.
02 Login, 11 Senarai jenis, 12 Upload (pilih PDF), 13 Senarai dokumen, 14 Download.
dokumen_id diisi automatik selepas upload. Jangan run seluruh koleksi: ada request yang mencipta atau mengubah data sebenar.

CARA SIMPANAN
Fail sebenar: bucket private dokumen-persiapan, laluan paket_id/UUID.pdf.
Maklumat dokumen: public.dokumen.
Lokasi fail, SHA-256, saiz, nama dan versi 1: public.dokumen_versi.
Catatan upload: audit_trail.
Fail diupload terlebih dahulu dengan token pengguna; pendaftaran metadata mengesahkan objek Storage milik pengguna, saiz dan MIME, kemudian menyimpan dokumen, versi dan audit dalam satu transaksi SQL.
Fail dan transaksi database bukan satu transaksi bersama. Jika pendaftaran ditolak dengan pasti, backend cuba membuang fail yang belum didaftarkan. Jika respons gagal secara tidak pasti (contohnya timeout), fail dikekalkan supaya rekod yang mungkin sudah berjaya tidak dipadam. Keadaan itu perlu disemak sebelum cuba upload semula.
Dokumen hanya muncul selepas pendaftaran berjaya. Hash dan saiz diperiksa semasa download. Download melalui backend dengan token pengguna, bukan URL public.

HAD LANGKAH INI
PDF sahaja, maksimum 10 MiB. Sambungan .pdf, MIME application/pdf dan penanda awal/akhir PDF diperiksa; ini bukan pengesahan penuh kandungan PDF.
Penyedia upload ketika paket DRAFT. PIC membaca mengikut Balai dan scope paket; Admin/Direktorat membaca mengikut aturan yang telah dipersetujui.
Fail berdaftar tidak boleh di-overwrite atau dipadam melalui akses pengguna biasa. Upload berulang menghasilkan dokumen baru; penggantian versi belum dibina.
Belum termasuk pautan bukti_dokumen_id pada jawapan checklist, syarat dokumen wajib, submit, review, frontend atau SMD.
Muat naik fail ujian tanpa data sensitif untuk ujian pertama.

VALIDASI
TypeScript dan 49 ujian API simulasi lulus termasuk upload/download binari, saiz, peran, PDF palsu, hash download dan pembersihan fail selepas pendaftaran ditolak.
Ujian SQL sebenar lulus untuk akses dokumen/versi dan ungkapan policy Storage bagi semua 36 akaun. Ujian tidak menulis metadata Storage melalui SQL.
Upload/download Storage sebenar dan transaksi pendaftaran selepas upload BELUM diuji sepenuhnya; ia dilakukan bersama dari laptop selepas bucket dibuat.
Perubahan dibuat pada project baru Jala-Mutu sahaja. Rekod ujian SQL di-rollback. 64 tabel public lain masih belum mempunyai policy.
