LANGKAH 5 — PAUTAN BUKTI KEPADA CHECKLIST

PASANG
1. Hentikan backend: Ctrl+C.
2. Backup folder backend.
3. Extract ZIP dan copy kandungan backend ke backend asal, pilih Replace.
4. .env, bucket dan fail PDF yang sudah diupload tidak perlu diubah.
5. Jalankan satu demi satu dalam folder backend:
   npm run typecheck
   npm test
   npm run dev
Ada 57 ujian API simulasi, semuanya sepatutnya lulus. Tiada package baru pada langkah ini.

UJIAN PERTAMA — BACA CHECKLIST
Login semula Penyedia jika token tamat.
GET http://localhost:5000/api/paket/3/checklist-persiapan
Authorization: Bearer Token Penyedia. Body: none.
Cari item Laporan Pendahuluan. Ada kolum baru jenis_bukti_kode: LAPORAN_PENDAHULUAN.
Baca pengisian.versi terkini. Semasa update disediakan, versi ialah 1, item laporan ID 15 dan dokumen PDF ujian ID 2. Jangan anggap versi kekal jika ada simpanan lain.

PAUTKAN DOKUMEN
PATCH http://localhost:5000/api/paket/3/checklist-persiapan/bukti
Authorization: Bearer Token Penyedia.
Body > raw > JSON:
{
  "expected_version": 1,
  "item_id": 15,
  "bukti_dokumen_id": 2
}
Ganti versi/ID dengan nilai sebenar jika berlainan. Klik Send sekali.
Respons 200, item Laporan Pendahuluan mendapat bukti_dokumen_id=2 dan versi menjadi 2 jika versi awal 1.
Jawapan item itu tidak ditukar kepada Ya secara automatik. Dua jawapan ujian terdahulu kekal, dan peratus terisi kekal 8% selagi jawapan lain tidak diubah.
Ulang GET checklist untuk sahkan pautan.

PADANAN
DOK-01: Laporan Pendahuluan -> LAPORAN_PENDAHULUAN.
DOK-09: Program Mutu / Quality Management Plan -> PROGRAM_MUTU.
Padanan disimpan dalam checklist_item.jenis_bukti_kode. Item lain belum dibuka untuk pautan bukti.

BUANG PAUTAN (PILIHAN, BUKAN LANGKAH WAJIB)
Gunakan endpoint PATCH bukti yang sama dengan versi terkini dan bukti_dokumen_id:null.
Ini hanya mengosongkan pautan. Fail Storage dan rekod dokumen kekal. Jawapan dan catatan tidak berubah.
Pautan sama yang disimpan semula tidak menghasilkan audit atau versi tambahan.

ATURAN
- Hanya Penyedia aktif, paket DRAFT dan pengisian DRAFT.
- Dokumen mesti TERSEDIA, jenis sepadan, paket sama dan versi aktif mempunyai fail dalam Storage.
- Setiap perubahan pautan menaikkan versi dan merekod audit dalam transaksi yang sama.
- Versi lama: 409; PIC cuba pautkan: 403; item/dokumen tidak sepadan: 400.
- Jawapan checklist biasa masih disimpan melalui endpoint asal. Jangan hantar bukti_dokumen_id di dalam senarai jawaban pada endpoint asal.
- PDF ujian Debian hanya bukti teknikal bahawa fail boleh dilampirkan; bukan laporan pendahuluan yang sah. Review kandungan, kelulusan dan syarat submit belum dibina.

POSTMAN PILIHAN
Import backend/postman/Jala-Mutu-Langkah-5.postman_collection.json.
Isi Variables dan login Penyedia. Jalankan 09 (baca), tetapkan dokumen_id sebenar, 15 (pautkan), 09 (baca semula). Koleksi mengambil ID item laporan secara automatik.
16 ialah unlink pilihan. Jangan jalankan seluruh koleksi kerana ada request yang mengubah data sebenar.

DATABASE DAN VALIDASI
Perubahan fungsi/padanan sudah dipasang pada Jala-Mutu; jangan run SQL lagi.
Ujian SQL menggunakan PDF yang telah diupload, tetapi semua pautan dan perubahan ujian di-rollback. Jawapan pengguna dan fail tidak diubah kekal oleh assistant.
TypeScript, 57 ujian HTTP simulasi dan ujian SQL sebenar lulus: pautan/unlink, peran, dokumen jenis/paket lain, konflik versi, kunci draft dan audit rollback.
